# Runtime upgrades with existing models

A runtime upgrade should build and check the engine once, find its locally installed recipes, and serve their existing model files wherever the new engine can read them. Installing a model remains an explicit preparation step. The first acceptance case is Strata v0.2.21 to v0.2.23 with ISTA GSQ-RCO IQ3_XXS and Unsloth UD-IQ3_XXS on the RX 9070 XT.

## Where the work goes today

| Artifact | Current behavior | Proposed upgrade behavior |
|---|---|---|
| Published Strata GGUFs and vision projector | Existing shards are verified locally. A new preparation can fetch missing files. Both recipes already share the locked Q8_0 projector and its BF16 source. | Keep their paths and bytes. A valid Q8_0 projector suffices for serving even if its conversion source is absent. |
| Strata pack and tokenizer | A fresh build key runs `iq_pack.py` again. ISTA uses the standard path. Unsloth uses `--compat-bf16` to convert selected small tensors to the representation the engine reads. Native attention projections and quantized experts stay in the GGUF. | Reuse the complete pack from the same target shards and packing options, including its indexes, dense data, tokenizer, and conversion records. Keep ISTA and Unsloth packs separate. |
| Strata MTP | Both recipes already share the verified BF16 source. Each recipe and new build key still runs `mtp_pack.py` to produce Q2_0 and `mtp_rt.py` to produce the runtime files, then copies the draft vocabulary. | Reuse a compatible completed MTP runtime, including across the two recipes when its inputs match. Require the source tensors or intermediate GGUF only for stages that actually need them. |
| ExLlamaV3 target and DFlash2 draft | The target EXL3 and the original draft have per-recipe download receipts. A new build normally verifies both and converts the draft again because its directory and receipt are tied to the build. | Load the existing target and try the converted 3 bpw draft with the candidate. Reconvert only when the draft inputs, requested quantization or required format change. |
| Attention KV cache and recurrent state | Serving allocates these for the running instance. Cache precision and context length are launch settings. | Recreate runtime state on startup. A cache setting or server restart should never trigger a weight download or draft conversion. |

The build coupling is in both [Strata preparation](../../runtimes/strata/scripts/prepare_models.py) and [ExLlamaV3 draft validation](../../runtimes/exllamav3-tabbyapi/scripts/serve.py). For the first trial, the tagged source trees have identical Git blobs for `iq_pack.py`, `mtp_pack.py`, `mtp_rt.py`, `mtp_fetch.py`, and `draft_vocab.bin`. That makes existing output a good reuse candidate. The engine reader and imported helpers also matter, so confirm it by loading and generating with the candidate. [Upstream source comparison](https://github.com/Niko1221/Strata/compare/v0.2.21...v0.2.23)

## Implementation order

1. **Make reuse a per-artifact decision.** Separate the exact image lock used to run a trial from the provenance of the files it consumes. Keep source revisions, checksums, conversion arguments and original producer identity. For a target pack match the ordered shard identities, packing options and readable pack format. For MTP match the source tensor identities, quantization, runtime layout and vocabulary digest. For DFlash2 match the draft source, model compatibility, conversion settings and readable EXL3 format. ROCm, PyTorch, server and engine revisions remain in the trial record. Changing one alone should not invalidate model bytes. If upstream has no reliable format version, validate the existing output with the candidate reader. Keep verification of the actual container image against its build lock.
2. **Reuse existing preparations in place.** Start with the current active preparation as a donor and support legacy receipts from existing installations. Keep the existing `prepared/<key>/` launch paths. Stage candidate directories with hard links to verified, immutable payload files on the same filesystem and write fresh candidate receipts carrying the original producer information. Never share writable metadata, converter work directories or runtime caches. Prefer a reflink on filesystems that support it if hard links are unavailable; report the size and require an explicit choice before a full cross-filesystem copy. Existing preparations need no bulk migration. Keep real files available after either trial directory is removed.
3. **Separate local upgrade from acquisition and repair.** Inspect final serving files first. Use existing receipts and file sizes on the normal path, with digest verification when importing legacy or untrusted data, when files change, or on explicit verification. Validate a complete output inventory, including any shard references, before reusing a pack. For a known format or input change, regenerate only the affected artifact from verified local inputs. If weights are missing or damaged, identify the recipe and file and print the explicit preparation command. A failed load caused by low VRAM, a driver, or a server error should keep the previous preparation intact and report the failure. Keep model fetching disabled throughout the upgrade preparation, including inside upstream helpers; engine and container image downloads are still part of a fresh build.
4. **Make the universal CLI operate on a runtime.** The proposed `python3 scripts/upgrade_runtime.py strata --release v0.2.23` discovers installed Strata recipes under the selected data root. Keep recipe IDs as the single-model form. Reuse the existing runtime discovery and trial-management logic, with installation detection appropriate to each adapter. Report missing files in partial installations and skip catalog-only recipes. Resolve and smoke-test once per distinct compatible image lock. Validate every selected model lock before preparation, persist the selected recipe list, and print a brief reuse or rebuild reason per artifact. Resume the saved list after interruption. Keep adoption separate, with a baseline command per recipe. Point the guides at this entry point and keep existing trial keys manageable.
5. **Update consumers together.** Make preparation, serving, doctor, adoption and deletion agree on the candidate receipt and artifact paths. Keep doctor read-only and inexpensive. Use the preparation lock and atomic publication so interruption cannot leave a successful receipt for incomplete work. Baseline import should still validate the exact running image and recipe settings. Confirm that rollback restores the old selection and deleting a trial only removes files it owns. Update the runtime guides, launcher guide and container setup template alongside the behavior change.

### Integrity and adoption safeguards

- A legacy Strata receipt has no independent digest for generated outputs. Check the legacy layout, shard references, and the locked GGUF hashes on import; capture generated-output digests for future verification. This cannot detect arbitrary pre-existing same-size corruption without a trusted reference. Do not overwrite a hard-linked payload during repair.
- Preserve the original producer separately from the candidate image lock. Keep reuse provisional until the candidate baseline exercises its model reader. Adoption requires confirmation for the saved recipes, and the exact smoke-tested image must still be selected.
- Enforce the local-only boundary in the preparation container with networking disabled. Copy only with explicit permission when neither links nor reflinks work; recipes that share a filesystem should share payload inodes, not writable receipts or work directories.

## Acceptance checks

- CPU tests use two installed Strata fixtures and one catalog-only fixture. Upgrade once with model downloads and converter calls set to fail the test. Both installed recipes must reuse their compatible artifacts, keep distinct packs, share eligible MTP payloads and build one image. Repeat for a ROCm-only change and for an ExLlamaV3 candidate with an existing converted draft.
- Change one input at a time. A different target shard or `compat_bf16` setting invalidates its pack. A vocabulary-only change updates the MTP vocabulary without requantizing the experts. Changed draft quantization rebuilds the draft only. Missing conversion sources must not block reuse of validated serving files. A corrupt serving file must fail verification.
- Exercise an existing versioned preparation with legacy receipts, an interrupted preparation and retry, and deletion in either order. Verify donor hashes, shared-file survival, and that valid payloads occupy no additional data blocks on the normal same-filesystem path.
- On the workstation, run the candidate against each installed quant with model fetching disabled. Check text generation, nonzero accepted MTP tokens, vision with the shared projector, and the long-context baseline. Compare disk allocation and confirm zero model-weight bytes fetched and zero converter invocations on the compatible path. Repeat load and drafting checks for ExLlamaV3 before enabling its reuse path. A successful image or HIP smoke test alone cannot validate a stored model format.
